Adcraft documentation

Everything needed to install, configure, deploy and rebrand your copy. Read Requirements and Third-party licensing before you start — both contain things that are easier to know now than to discover later.

What this is

Adcraft is a complete multi-tenant SaaS for making and running paid-social ads with AI. A user imports a brand from a website address, adds a product, writes a brief, gets eight ad concepts from Claude, turns one into static ads, a product video or an AI-presenter video in every placement size, publishes to Meta, TikTok or Google Ads, and reads performance back.

It ships as a pnpm monorepo: one Next.js 15 application plus seven internal packages. You host the application. Connected integrations send requests to the services you configure.

It runs with zero API keys. Text concepts return labelled samples without provider keys. Sandbox ad accounts simulate campaigns and metrics. The static ad studio requires a connected image provider before it enables generation. The live HeyGen catalog, voice tools and some other features need a connected provider. Add keys to enable those services.

Requirements

Node.js22 or newer
pnpm9.15.9 (corepack enable installs it from the repo's own setting)
PostgreSQL15 or newer, 18 recommended. Optional locally — an embedded database starts automatically when DATABASE_URL is blank.
FFmpegNeeded for presenter/UGC video only. Installed automatically by ffmpeg-static, or point FFMPEG_PATH at your own build.
HostingA persistent Node server — a container host, a VPS, Railway, Render, Fly. Not a pure serverless host: video rendering and the job runtime need a long-lived process and a writable disk.
RAM1 GB to run, 2 GB+ if you render video on the same machine.

Shared hosting and cPanel will not work. This is a Node.js application, not PHP. If your host cannot run node as a persistent process, it cannot run Adcraft.

Install locally

  1. Unzip and install dependencies

    cd adcraft
corepack enable
pnpm install --frozen-lockfile

  2. Create your environment file

    cp .env.example .env

    Open .env, leave DATABASE_URL blank for local use, and set your own secret:

    AUTH_SECRET=<paste the output of: openssl rand -base64 32>

  3. Start it

    pnpm --filter @adcraft/app dev

    Open http://localhost:3000 for the marketing site and /dashboard for the product. With no email provider configured, the sign-in page shows a development box where any address signs you straight in.

  4. Point it at a real database when you are ready

    Set DATABASE_URL in .env, then apply the schema:

    pnpm --filter @adcraft/db db:migrate

    Until you do, an embedded PostgreSQL runs from .data/pglite — fine for a look around, not for production.

Your first ad

  1. Sign in, and the welcome flow asks for a workspace name, a brand name and a website address.
  2. Adcraft reads that website and builds a brand kit: logo, colour palette, fonts, tagline and tone of voice.
  3. Paste a product page address. The product is imported and its background removed.
  4. Write a brief — or press Write the brief and let the model draft it.
  5. Eight concepts stream in. Select one and press Make the ad.
  6. Choose sizes and generate. Each render costs credits; the cost is shown before you commit.

Without a text provider, concepts use sample output. Image generation in the static studio needs a connected image provider. Website import needs internet access; you can also enter the brand and product details by hand.

Feature walkthrough

Every screen in the order a user meets it. The label above each heading is where it lives in the left-hand navigation, so you can follow along in your own install.

Overview

Dashboard

The landing screen after sign-in. It greets the user by time of day, shows credits remaining against the plan allowance, and surfaces anything needing attention: failed generations, requested changes, fatigued ads and a low-credit warning. The Create button opens a menu shortcutting straight to a static ad, a product video or a presenter video.

Brand kits

Brand kit

Paste a website address and Adcraft reads it, then fills the kit: logo, five colour roles, heading and body fonts, tone of voice with do-say and don't-say lists, tagline and CTA style. The live preview on the right updates as you type. Every save creates a new version, so ads made earlier keep the kit they were made with.

Product library

Product library

Every product available to the brand. Add one by uploading a photo or by pasting a product page address — Shopify product data, JSON-LD and Open Graph are all read for name, description, price and images.

Product library

A single product

The product's details with its original photo and the cut-out version beside it. The background is removed automatically on import so the product can sit in any generated layout. Brief with this product carries it straight into a new brief.

Briefs

Writing a brief

The input step: title, product, objective, audience, offer, platforms and formats. Each field has an assist button, and Write the brief drafts the whole thing from what little you have. Formats chosen here decide which builders and sizes are offered later.

Briefs

Eight ad ideas

Ideas stream in one at a time as the model writes them, so the first is usable before the last is finished. Each carries a hook, an angle, headline and body copy, a call to action, suggested platforms and a visual direction. Select the ones worth making; reject the rest and they stay on record.

Ads

A finished image ad

One idea rendered in every size the brief asked for. Switch sizes with the ratio tabs. The panel on the right offers approval, a share link for a client, a variant, a refinement instruction to regenerate the picture, and a download of every size as a ZIP.

Ads

Product video

The storyboard, one card per scene, each with its still, its clip, an editable caption and the prompt used. Captions re-assemble instantly; changing a prompt regenerates only that scene. The finished cut is produced in landscape, portrait and square.

Character studio

UGC templates

Six ready-made presenter video structures to start from — each sets the pacing, the hook placement and where product shots cut in.

Character studio

Presenter video builder

Choose the format, the video model for B-roll, the primary size, then who presents it and in which voice. The storyboard below fills in as each part lands: voice-over, presenter take, B-roll clips, then the assembled sizes.

Character studio

Cast library

Browse the presenters available through your connected provider account, filtered by gender and by type — filmed studio, AI avatars and digital twins. Pick a person, then one of their looks.

Character studio

Looks

The outfits and settings available for a chosen presenter, so the same face can appear in different contexts across a campaign.

Campaigns

Campaign builder

Five steps: where it runs, who sees it, placements and budget, which ads, then review. The review step validates every asset against that placement's exact specification and runs the claims check over the copy. Campaigns publish paused.

Campaigns

Campaigns

Every campaign with its platform, status and spend. Connect Meta, TikTok or Google Ads here; without credentials each platform runs in sandbox so the whole flow stays testable.

Performance

Performance

Spend, impressions, clicks, CTR, CPA and ROAS per campaign and per creative, synced hourly. Fatigue alerts flag ads whose performance is sliding, with one click to open a fresh brief pre-filled from the winner, or to pause.

Ads

Client review

A share link lets a client see every size, leave comments and approve, with no account and no access to anything else in the workspace.

Settings

Team

Invite people as owner, editor or viewer. Owners manage billing and approve spend above the threshold; editors create and publish; viewers look and comment.

Settings

Plans and credits

The subscription plans, the current balance and the credit ledger. Every generation reserves credits up front and refunds them if it fails.

Settings

Guardrails

Workspace limits: the daily budget above which an owner must approve, the monthly credit cap, and generation rate limits.

API access

Admin

Admin console

Platform-wide: organisations, users, billing, provider health, cost per model, the AI model catalogue, recorded errors, the audit log and feature flags. Available to any address listed in ADMIN_EMAILS.

Environment keys

.env.example lists all 59 settings with comments. The ones that matter most:

AUTH_SECRETRequired. openssl rand -base64 32
AUTH_URLYour public address in production, e.g. https://ads.example.com
DATABASE_URLPostgreSQL connection string. Blank uses the embedded database.
ADMIN_EMAILSComma-separated. These addresses become platform admins on sign-in.
DEV_LOGINSet to 0 in production to hide the development sign-in box.

Admin → Providers shows the same list with live status, so you can see at a glance which integrations are on. Admin → Models lets you add, disable or re-point any AI model without a redeploy.

Ad platforms

Each platform needs a developer application of your own. Without one, that platform runs in sandbox mode: campaigns are simulated and metrics are generated, which is enough to demonstrate and test the entire publishing flow.

Meta (Facebook & Instagram)META_APP_ID, META_APP_SECRETdevelopers.facebook.com — Marketing API
TikTokTIKTOK_APP_ID, TIKTOK_APP_SECRETbusiness-api.tiktok.com
Google AdsGOOGLE_ADS_CLIENT_ID, GOOGLE_ADS_CLIENT_SECRET, GOOGLE_ADS_DEVELOPER_TOKENGoogle Ads API centre

Set the OAuth redirect of each application to https://your-domain.com/api/connect/<platform>/callback.

Platform review takes time. Meta, TikTok and Google each review an application before it may serve users other than you. Plan for days to weeks. Until then your app works on your own ad accounts, and everyone else sees sandbox mode. This is how every ad tool works; it is not a limitation of this item.

Stripe billing

Three subscription plans and a credit top-up are defined in apps/app/src/server/billing.ts. Create matching products and prices in your own Stripe account:

  1. Create monthly and yearly recurring prices for Starter, Studio and Agency. Set product metadata plan to starter, studio or agency, and credits to the matching plan allowance in billing.ts.
  2. Create a one-time credit top-up price. Set its product metadata credits to the top-up amount defined in billing.ts.
  3. Copy the price IDs into the matching STRIPE_PRICE_* fields in .env. Set STRIPE_SECRET_KEY.
  4. Create a webhook at https://your-domain.com/api/stripe/webhook for checkout.session.completed, customer.subscription.created, customer.subscription.updated, customer.subscription.deleted and invoice.paid. Set its signing secret as STRIPE_WEBHOOK_SECRET.
  5. Test checkout, credits and cancellation with Stripe test mode before enabling live billing.

Billing is optional. Leave STRIPE_SECRET_KEY blank and the plan pages hide themselves; grant credits by hand from Admin → Organisations.

Background jobs

Generation and publishing run as background jobs with retries, concurrency limits and cron schedules, through Inngest.

  • Without configuration the same pipelines run inline in the web process. Simplest, and fine for a small installation.
  • With INNGEST_EVENT_KEY and INNGEST_SIGNING_KEY jobs move to Inngest Cloud, which adds retries, a dashboard and the hourly insights sync. Point its app at https://your-domain.com/api/inngest.

Locally, pnpm inngest starts the Inngest dev server against your app.

File storage

Generated images and video are written to a local directory by default (LOCAL_STORAGE_DIR, served through /api/files). Set the four R2_* variables to use Cloudflare R2 — or any S3-compatible bucket — instead. Keys are scoped per workspace, and a file is served only to members of the workspace that owns it.

On a container host, point storage at a mounted volume or a bucket. A container's own filesystem is wiped on every deploy, taking every generated asset with it.

Deploy to production

A Dockerfile is included and builds a production image that runs as an unprivileged user, applies database migrations on boot and serves on $PORT. Any host that runs a container will do.

  1. Provision PostgreSQL

    Set DATABASE_URL. Migrations run automatically at startup.

  2. Set the environment

    Set AUTH_SECRET, AUTH_URL, DATABASE_URL, ADMIN_EMAILS and DEV_LOGIN=0. Configure Resend or Google sign-in: development sign-in is disabled in production.

  3. Attach durable storage

    A mounted volume at LOCAL_STORAGE_DIR, or the R2_* variables.

  4. Build and run

    docker build -t adcraft .
docker run -p 3000:3000 --env-file .env adcraft

  5. Check it

    GET /api/health reports the database, storage and job runtime with latency, and returns 503 when the database or storage is failing. Point your uptime monitor at it.

documentation/DEPLOY.md in the package has host-specific notes.

Branding and customisation

Adcraft is meant to be sold under your own name. Nothing below needs a build step beyond restarting the dev server.

1. Colours

Every colour in the application comes from one token file, packages/ui/src/tokens.css. Change a value there and the whole product follows — buttons, panels, charts, emails and the admin console. The same file defines the dark theme further down, so set both.

:root {
  --paper:   #f8f7f3;   /* page background        */
  --ink:     #242521;   /* primary text           */
  --muted:   #75756d;   /* secondary text         */
  --orange:  #e65c32;   /* accent: buttons, links */
  --line:    #e4e3dc;   /* borders and dividers   */
  --surface: #ffffff;   /* cards and panels       */
}

packages/ui/src/tokens.ts mirrors the same values for code that needs them in JavaScript (the ad renderers, chart colours). Keep the two in step.

2. Logo and wordmark

The mark is a single component at apps/app/src/components/spark.tsx, which exports both the symbol and the full wordmark. Replace the SVG inside it with your own and every placement updates: the sidebar, the sign-in page, the onboarding screens, the email templates and the ad end-cards.

Sizes are passed as props rather than hard-coded, so a wider logo needs no layout changes.

3. Favicons and app icons

Replace these in apps/app/public, keeping the file names:

  • favicon.svg — modern browsers
  • favicon.ico — Safari and older browsers; needs 16, 32 and 48px frames inside the one file
  • favicon-32.png, apple-touch-icon.png — 32×32 and 180×180

4. Typography

Heading and body faces are set in tokens.css as --sans and --serif. The project loads them from Google Fonts in apps/app/src/app/layout.tsx; swap the link and the token together. The fonts offered to your customers for their own brand kits are a separate list in apps/app/src/lib/brand-kit.ts (KIT_FONTS).

5. Product name and copy

Search the project for Adcraft. It appears in page titles, the sign-in and welcome screens, email subjects and the legal pages. The legal pages themselves — terms, privacy and DPA — are at apps/app/src/app/(legal)/ and must be reviewed for your own company before you launch.

6. Marketing website

The public site lives in dist/ as plain HTML, CSS and JavaScript with no build step: index.html, style.css and app.js, plus the showcase and pricing pages. It is copied into the application's public folder automatically whenever you run dev or build, so edit it in place and refresh.

7. Plans, prices and credit costs

Both live in apps/app/src/server/billing.ts: PLANS sets the names, monthly prices, credit allowances and per-plan limits; CREDIT_COSTS sets what each action costs a customer. Change them before running the Stripe setup script so your catalogue matches.

8. Ad layouts

The four image-ad templates are React components in packages/render/src/static/templates.tsx. Each receives the brand kit, the copy and the product cut-out, so a new layout is a new component in the same shape plus an entry in the exported list.

Backups & health

A nightly job dumps the database with pg_dump, gzips it, writes it to your bucket under db/ and prunes past BACKUP_RETENTION_DAYS (14 by default). It needs a pg_dump whose major version matches your server; the included Dockerfile installs the PostgreSQL 18 client.

Unhandled server errors are recorded and listed at Admin → Errors. Set SENTRY_DSN to mirror them to Sentry as well.

API reference

A read API for pulling finished creatives into your own systems, plus outbound webhooks. Create keys at Settings → API access; a key is displayed once and stored hashed.

Authentication

Send the key as a bearer token. Every request is scoped to the organisation that owns the key.

curl https://your-domain.com/api/v1/creatives \
  -H "Authorization: Bearer ak_live_..."

A missing or invalid key returns 401 with a JSON error body.

GET /api/v1/creatives

Lists the organisation's creatives, newest first, each with a render URL per size.

ParameterNotes
brandIdOptional. Restrict to one brand.
limitOptional integer 1–200, default 50. Anything else returns 400 invalid_limit.
cursorOptional. Pass the previous response's next_cursor for the next page.

Responds with { "data": [ ... ], "next_cursor": "..." }. When next_cursor is null there are no further pages.

GET /api/v1/creatives/:id

One creative with its concept, every size and the render status of each. Returns 404 when the id does not belong to the key's organisation.

GET /api/v1/files/:key

Streams a stored file. Keys are workspace-scoped, so a key can only read files belonging to its own organisation.

Webhooks

Register endpoints at Settings → API access. Each delivery is signed with the endpoint's secret so you can verify it came from your installation.

EventFires when
creative.renderedEvery size of a creative has finished rendering
approval.approvedA creative is approved
approval.changes_requestedA reviewer requests changes
comment.addedA comment is added, including from a share link

Third-party licensing

Read THIRD-PARTY-NOTICES.md in the package. The short version:

Remotion, used by the product-video renderer, is free for individuals and organisations of up to three people. Larger organisations need a paid licence from remotion.pro, and because Adcraft renders programmatically, such an organisation falls under Remotion's metered "Automators" tier with a monthly minimum. The obligation is between you and Remotion AG.

This affects the product-video feature only. Static ads, presenter/UGC video, publishing and performance never load Remotion, Do not delete renderer source files to disable the feature; avoid using product-video rendering until your licensing requirements are met.

FFmpeg (presenter/UGC assembly) is fetched at install time under GPL terms; point FFMPEG_PATH at your own build if you prefer. Satori and resvg are MPL-2.0, which places no obligation on your own source. Everything else is MIT, Apache-2.0 or ISC.

Troubleshooting

pnpm install fails

Check node -v is 22 or newer, then corepack enable so the pinned pnpm is used.

The database will not connect

Confirm DATABASE_URL, then run pnpm --filter @adcraft/db db:migrate. /api/health reports which check is failing.

Generation returns obviously fake output

That is sandbox mode: the provider key for that capability is missing. Check Admin → Providers.

Website import finds no colours or logo

Some sites block automated readers, and some render entirely in JavaScript. Set the brand kit by hand in Brand kits; nothing downstream depends on the import succeeding.

Video renders fail or run out of memory

Video rendering needs roughly 2 GB and a writable temporary directory. Raise the container's memory, or move rendering to a bigger worker.

Stripe checkout succeeds but no credits arrive

STRIPE_WEBHOOK_SECRET is missing or wrong. Check the webhook endpoint in your Stripe account and copy its signing secret into the matching environment field.

Published campaigns are not real

No developer credentials for that platform, so it is in sandbox mode. See Ad platforms.

Support

For supported purchases, support covers questions about the documented features and reported defects. Installation services and custom development are separate. It does not cover your hosting, third-party accounts and their review processes, provider bills, or custom development.

When reporting a problem, include: the page or action, what you expected, what happened, the output of /api/health, and the matching row from Admin → Errors. Remove secrets and customer data before sharing logs.
